# Окружение видеопайплайна для Vast.ai

Статус: проект спецификации, ожидает утверждения Ани. Код и облачные ресурсы ещё не созданы.

## Контекст

Аня хочет повторно запускать весь видеопайплайн на одной RTX 3090 или RTX 4090 с 24 GB видеопамяти. Аккаунты Vast.ai, Docker Hub `anyakeller` и GitHub `anya-keller` доступны через Secret Agent.

На Mac нельзя устанавливать Docker, запускать контейнеры или собирать образ. Для сборки используем удалённый GitHub Actions. На Mac допускаются исходные текстовые файлы и эта спецификация.

Существующий каталог `video-creation` содержит Three.js-проект. Его не меняем. Новую конфигурацию храним отдельно в `vast-video-pipeline`.

## Цель

Подготовить образ со всем программным окружением и сохранить шаблон Vast.ai для его запуска. Подтвердить сборку в CI и отдельно проверить весь видеопайплайн на согласованной GPU. До реального GPU-прогона не объявлять окружение полностью проверенным.

## Предлагаемые ресурсы

Требуют подтверждения до создания:

- приватный GitHub-репозиторий `anya-keller/vast-video-pipeline`;
- приватный Docker Hub-репозиторий `anyakeller/vast-video-pipeline`;
- шаблон Vast.ai `H3 Video Pipeline — RTX 3090/4090`, без публикации в общий каталог;
- стандартный Linux x64 runner GitHub Actions, сборка только для `linux/amd64`;
- первый коммит и последующие коммиты только по явному разрешению Ани.

Если имя занято, нужный приватный репозиторий недоступен по тарифу или возникнет платное действие, остановиться и согласовать решение. Не менять существующие репозитории и глобальные настройки оплаты.

## Что изменится

После утверждения создаём:

1. `Dockerfile`, `.dockerignore`, `.gitignore`: образ и исключения для моделей, результатов, токенов и локальных файлов.
2. `config/components.lock.json`: версии базового образа, Python, PyTorch/CUDA, ComfyUI, расширений и нативных библиотек.
3. `config/models.lock.json`: перечень весов, исходные репозитории, неизменяемые ревизии, размеры, контрольные суммы и относительные пути.
4. `config/presets.json`: режимы H3 и параметры очистки/апскейла для 24 GB.
5. `scripts/prepare-models.sh`, `scripts/start.sh`, `scripts/doctor.sh`: подготовка моделей, запуск интерфейса и диагностика.
6. `postprocess/`: типизированная реализация V-BM3D refinement и точка входа VapourSynth.
7. `workflows/`: проверенные JSON-workflow для H3, FlowDenoise и SeedVR2 с согласованными именами моделей и узлов.
8. `tests/`: тесты конфигурации, повторного запуска, обработки ошибок и подготовки входов V-BM3D.
9. `.github/workflows/build.yml`: удалённые линтеры, тесты, сборка, проверка контейнера и публикация образа.
10. `vast/template.md`: поля шаблона, ссылка на сохранённый шаблон и проверенный идентификатор образа, без секретов.
11. `README.md`, `CONTEXT.md`: инструкция запуска и журнал проблем в формате `[ДАТА] Проблема: X → Решение: Y`.

## Детали реализации

### Программное окружение

Включить ComfyUI, H3/Turbo и зависимости исходного RTX 30-series workflow, FlowDenoise, VideoHelperSuite, SeedVR2, FFmpeg, VapourSynth, V-BM3D и BestSource. Не ограничиваться Python-пакетом VapourSynth: проверить наличие `vspipe` и рабочих нативных плагинов.

До первой сборки проверить исходные репозитории, лицензии и совместимость версий. Закрепить базовый образ по digest, исходники по commit SHA, зависимости по версиям. Не использовать плавающие `latest`, `main` и безусловный `pip install -U` в повторных запусках.

Устанавливать зависимости в образ, а не переустанавливать их при каждом старте Vast. Если VapourSynth требует отдельного Python-окружения, изолировать его внутри того же контейнера. Это остаётся одним GPU-инстансом.

Секреты не включать в Dockerfile, слои, аргументы сборки, логи или файлы конфигурации.

### Модели и данные

Веса не включать в Docker-образ и GitHub: они занимают десятки гигабайт и хранятся отдельно от программного окружения. `prepare-models.sh` получает пути из конфигурации, проверяет свободное место и контрольные суммы, скачивает недостающие файлы с возобновлением и повторно использует исправные файлы. Параллельные старты защищены блокировкой; незавершённая загрузка не считается готовой моделью.

В набор входят веса H3 pruned INT8/ConvRot, текстовый энкодер, video/audio VAE, Turbo LoRA, RAFT и SeedVR2 7B Sharp mixed FP8 с нужным VAE. Точные имена и ревизии сверить с источниками, затем записать в manifest. Не подменять Sharp обычным SeedVR2.

Пути к моделям, входам, результатам и кэшу задаются конфигурацией. Программы из образа не должны исчезать при подключении каталога данных. Не скачивать тяжёлые файлы одновременно с генерацией.

Local volume Vast привязан к физическому хосту. При смене хоста нужен перенос или повторная загрузка данных; шаблон этого ограничения не снимает. Объём и платное создание хранилища согласуются перед арендой.

### Видеопайплайн

Сохранить возможности трёх прочитанных документов:

- H3 Turbo 4 шага для черновиков, 6–8 для финала; Base около 20 шагов как отдельный режим.
- FlowDenoise с RAFT Large и настройками для исходного разрешения. MEMFOF не добавлять без проверки лицензии и отдельного выбора.
- V-BM3D Final получает оригинальное видео как вход, а результат FlowDenoise как reference/basic estimate. Не заменять эту схему сильным последовательным двойным denoise.
- Перед refinement проверять разрешение, FPS и число кадров у оригинала и reference. При несовпадении прекращать обработку с понятной ошибкой.
- Между стадиями использовать lossless-последовательности или FFV1; не добавлять промежуточное сжатие H.264.
- SeedVR2 7B Sharp mixed FP8 для 24 GB, с настраиваемыми tiling, batch size и offload.
- Сохранять пропорции кадра; crop/pad выбирать явно. Не растягивать 744×488 в 3840×2160.
- Возвращать исходное аудио H3 в финальный файл и проверять синхронизацию.

Запускать GPU-стадии последовательно, освобождая память между ними. Старт контейнера открывает подготовленное окружение, но не генерирует видео без команды пользователя.

### Удалённая сборка и публикация

Использовать GitHub Actions и официальные Docker actions, закреплённые по SHA. Публикация запускается вручную, после линтеров, тестов и проверки образа. Простое открытие аккаунта или создание файла не должно запускать сборку и публикацию.

Стандартный Linux runner для приватного репозитория по документации предоставляет 2 CPU, 8 GB RAM и 14 GB SSD. Этого может не хватить для CUDA-образа. Перед сборкой проверить доступные ресурсы; ограничить параллелизм компиляции и не хранить веса/дублирующие архивы образа. Если сборка не помещается, не урезать пайплайн и не включать платный runner автоматически: согласовать другой удалённый сборщик.

Перед первым запуском проверить остаток бесплатной квоты Actions и условия остановки при её исчерпании. Если нельзя гарантировать отсутствие платного превышения, запросить решение Ани до запуска. Не менять бюджеты других проектов. Не включать тяжёлые платные кэши и длительное хранение артефактов.

После проверок отправить образ в приватный Docker Hub, записать digest и тег, связанный с ревизией исходников. До публикации первого коммита и образа получить явное разрешение Ани. Разрешение на одну публикацию не считать разрешением на произвольные последующие коммиты.

### Доступы

Для GitHub Actions нужен Docker Hub-токен с минимальными доступными правами на загрузку образа. Для Vast нужен отдельный доступ на чтение приватного образа. Пароли и токены не запрашивать в чате, не извлекать из браузерного хранилища и не включать в спецификацию. Создание и ввод секретов согласовать отдельно; пользователь может внести их в сервисы самостоятельно.

### Шаблон Vast

Настроить SSH-режим и on-start-вызов скрипта из готового образа. В этом режиме Vast заменяет Docker ENTRYPOINT, поэтому одного ENTRYPOINT недостаточно.

Фильтры: одна RTX 3090 или RTX 4090, не менее 24 GB VRAM и 64 GB RAM, x86_64 и совместимый NVIDIA-драйвер. Начальный ориентир диска для полного стека: 150 GB; перед арендой пересчитать по manifest моделей и планируемым промежуточным файлам.

ComfyUI слушает loopback внутри инстанса, пользователь открывает его через SSH-туннель. Не выставлять незащищённый интерфейс в интернет.

Указать приватный образ и настроить Docker Repository Authentication через предназначенное для этого поле. Шаблон не размещать в общем каталоге. Не считать приватность шаблона хранилищем секретов: документация допускает использование приватного шаблона по переданной ссылке.

Сохранить через Create, проверить появление в My Templates и повторно сверить поля. Не нажимать Rent, не создавать volume и не запускать GPU без отдельного согласования стоимости.

## Проверки и команды

Проверки кода и контейнера выполняются на удалённом runner; на Mac Docker не нужен.

- Dockerfile: `hadolint Dockerfile` и проверка сборки через Buildx.
- Shell: `shellcheck scripts/*.sh`, `shfmt -d scripts/*.sh`.
- CI: `actionlint .github/workflows/build.yml`.
- Python: `ruff check postprocess tests`, `ruff format --check postprocess tests`, `mypy --strict postprocess`, `pytest`.
- В тестах внешние сеть, файловая система и процессы заменены контролируемыми подстановками; тесты не скачивают настоящие модели и не арендуют серверы.
- Контейнерная проверка без GPU: версии библиотек, `vspipe`, FFmpeg, наличие BM3D/BestSource, конфигурация узлов, запуск диагностического режима без сети. Отсутствие GPU в CI не выдавать за GPU-проверку.
- После публикации: проверка manifest/digest и архитектуры `linux/amd64` через `docker buildx imagetools inspect` на удалённом runner.
- После отдельного разрешения на аренду: `nvidia-smi`, `doctor.sh --gpu`, короткая генерация H3 со звуком, FlowDenoise, reference-based V-BM3D, SeedVR2, возврат аудио. Проверка файла через `ffprobe` и просмотр результата.
- Повторный старт того же инстанса: исправные модели не загружаются заново, зависимости не переустанавливаются, ComfyUI доступен.
