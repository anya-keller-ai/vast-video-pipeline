# Четыре вкладки быстрых апскейлеров

Статус: **одобрено Аней**. Реализованы вкладки FlashVSR+ Turbo/Base, RealESRGAN x2plus и RealESRGAN AnimeVideo-v3 (backend, frontend, тесты, загрузка весов по прямой ссылке). **Исключены по правилу «без коммерческой лицензии не берём»: AnimeJaNai и SPAN 2xLiveActionV1.** Не реализован trtvideo (Docker). Деплой и запуск на GPU не выполнены (инстанс недоступен).

## Цель

Добавить в мастерскую четыре независимых таба апскейла видео (решение Ани: «каждый отдельным»):

| Таб | Скорость из таблицы Ани | Узел ComfyUI |
| --- | --- | --- |
| SPAN TensorRT | 100,1 fps (720p → 1440p), 48,6 fps (1080p → 4K) | **не определён** (см. «Открытые вопросы») |
| RealESRGAN x2plus | 10,4 fps (720p → 1440p) | встроенные узлы ComfyUI |
| FlashVSR+ Turbo | 0,98 fps (4K) | `kkget/ComfyUI-FlashVSR_Plus` |
| FlashVSR+ Base | 0,50 fps (4K) | `kkget/ComfyUI-FlashVSR_Plus` |

Источник таблицы и карта, на которой она снята, неизвестны. Цифры не считаются подтверждёнными для RTX PRO 5000 Blackwell.

## Проверенные факты (по README и исходникам в интернете)

- **FlashVSR+** (`kkget/ComfyUI-FlashVSR_Plus`, Apache-2.0): режимы Turbo, Base, V1; вход IMAGE/VIDEO; необязательная передача звука; веса в `ComfyUI/models/FlashVSR_Plus/{turbo,base,...}`; у загрузчика `auto_download=true` по умолчанию (нам нужно выключить: скачивание только кнопкой таба); нужен CUDA с BF16; внимание выбирается BSA → Triton → SDPA, Triton компилируется при первом запуске (на Blackwell SM120 не проверено); разработчик не проверял длинные видео. Масштаб по умолчанию `scale=1.0`, `height=width=0`: масштаб нужно задавать явно.
- **RealESRGAN x2plus**: работает на встроенных `UpscaleModelLoader` и `ImageUpscaleWithModel`, кастомный узел не нужен. Веса `RealESRGAN_x2plus.pth` (xinntao). Наличие узлов проверить на сервере через `/object_info`.
- **TensorRT-апскейл** (`yuvraj108c/ComfyUI-Upscaler-Tensorrt`): лицензия **CC-BY-NC-SA 4.0 (некоммерческая)**; в списке проверенных моделей SPAN нет (ESRGAN-семейство); поддерживает вход 256–1280 px по стороне; нужны TensorRT 10.x и сборка движка под конкретную карту. Для Blackwell и CUDA 13 не проверено.

## Дизайн (после ответов на вопросы)

1. **Манифест** (`config/models.lock.json`): по одному комплекту на таб (`span_tensorrt`, `realesrgan_x2plus`, `flashvsr_plus_turbo`, `flashvsr_plus_base`) с закреплёнными revision и SHA-256; скачивание только кнопкой таба. Общие файлы FlashVSR+ (decoder, prompt) входят в оба комплекта FlashVSR+.
2. **Custom nodes** (`config/custom-nodes.lock.json`): FlashVSR+ закрепляется commit-хэшем; backend их не устанавливает, а перед запуском проверяет `/object_info` и называет недостающие узлы (механизм `required_nodes` уже есть).
3. **Backend**: по builder-у на каждый таб в `web/backend/` (граф ComfyUI API), режимы API `span`, `realesrgan`, `flashvsr_turbo`, `flashvsr_base`, общий путь загрузки видео и выдачи результата как у SeedVR2 (исходный FPS и звук сохраняются). Сборка графов проверяется по живому `/object_info`, JSON-копии лежат в `workflows/` и сверяются тестом с builder-ом.
4. **Frontend**: четыре таба рядом с существующими (итого 8). Форма таба: видео, масштаб (×2 / ×4, где применимо), параметры модели (FlashVSR+: масштаб, tile, offload по умолчанию из README). Таймер, отмена и ошибки работают через существующий `JobManager`.
5. **Память и скорость**: перед стартом показывать честное предупреждение о риске OOM на 4K; замеры скорости делает Аня в UI, мы не выдаём цифры без запуска.

## Критерии приёмки

- [ ] Четыре таба открываются независимо; ни один не скачивает модели сам.
- [ ] Каждый комплект скачивается по кнопке и проходит проверку SHA-256.
- [ ] Граф каждого таба проходит `/object_info` живого ComfyUI без ошибок (до запуска на GPU).
- [ ] Тесты backend и frontend, lint, типизация, E2E и `git diff --check` без ошибок.
- [ ] Результат запуска на GPU не выдаётся за проверенный, пока Аня не запустила его.

## Дополнение: источники и решения Ани (2026-11-09)

Решения Ани: RealESRGAN делаем **обе модели** (x2plus и AnimeVideo-v3), загрузка весов с GitHub разрешена; SPAN и AnimeJaNai допустимо вынести во **внешний процесс** (вне ComfyUI).

Найдено при проверке источников:

- **Таблица Ани взята из README `egor-fedorov/trtvideo`** (Apache-2.0) и измерена на **RTX 4090**. Строки «SPAN» это модель `2xLiveActionV1_SPAN`, «RealESRGAN x2plus» это `RealESRGAN_x2plus`. Строки FlashVSR+ в этой таблице к trtvideo не относятся (источник не установлен). Для нашей RTX PRO 5000 Blackwell цифры не измерены.
- **trtvideo работает только через Docker** (`docker run --gpus all`), TensorRT-движок собирается под конкретную GPU (`build-engine`, экспорт ONNX отдельным образом model-tools). Мастерская идёт на контейнерном инстансе Vast.ai, где вложенный Docker с GPU обычно недоступен. **Не проверено, нужен доступ к новому серверу.**
- **SPAN как «neosr»**: `umzi2/neosr` это фреймворк обучения, а не готовые веса. Проверенная в trtvideo модель `2xLiveActionV1_SPAN` лежит на OpenModelDB.
- **AnimeJaNai** (`the-database/mpv-AnimeJaNai`): набор моделей для mpv, лицензия репозитория не определена (`NOASSERTION`). Готового узла ComfyUI нет; формат весов и условия использования не проверены.
- **Real-ESRGAN AnimeVideo-v3**: это отдельная модель (`realesr-animevideov3`) с релиза `xinntao/Real-ESRGAN`; RealESRGAN_x2plus из релиза v0.2.1 имеет SHA-256 `49fafd45f8fd7aa8d31ab2a22d14d91b536c34494a5cfe31eb5d89c2fa266abb` (67 061 725 байт). Загрузчик мастерской умеет только Hugging Face: нужен источник GitHub с проверкой SHA-256.

### Предлагаемый порядок (ждёт одобрения)

1. **Без Docker и TensorRT:** вкладки RealESRGAN x2plus, RealESRGAN AnimeVideo-v3 и SPAN (`2xLiveActionV1_SPAN`) на встроенных узлах ComfyUI `UpscaleModelLoader` и `ImageUpscaleWithModel` (поддержка архитектур через spandrel). Скорость заметно ниже, чем у TensorRT из таблицы.
2. **Загрузчик:** поддержка источника GitHub (release asset) и OpenModelDB в манифесте с обязательными размером и SHA-256, скачивание только кнопкой.
3. **trtvideo-путь (внешний процесс)** добавляется отдельно, только если на новом сервере подтвердится работа Docker с GPU и сборка движка на Blackwell.
4. **AnimeJaNai** откладывается до выяснения формата весов и лицензии.

### AnimeJaNai V3.1 (решение Ани: не откладывать)

Проверено по репозиторию `the-database/mpv-AnimeJaNai` (commit `d8cdb4ee45`):

- **Лицензия: CC BY-NC-SA 4.0 (некоммерческая, с копилефтом).** Допустимо только если проект не используется коммерчески. Вопрос открыт у Ани.
- **Веса только в ONNX** (fp16, opset 20, архитектура SPAN F3), вход `[1, 3, height, width]` с динамическим размером, лежат прямо в репозитории (0,7–2 МБ каждая). Встроенные узлы ComfyUI читают PyTorch-веса, ONNX они не загружают, поэтому нужен **внешний процесс**.
- Четыре HD-модели V3.1: `Balanced` и `Performance`, каждая в обычной и `Sharp1` версиях. SD V1 beta (Compact) и temporalfix не берём.
- SHA-256 фиксируются из репозитория: Balanced `b308e93c…`, Performance `7b804d87…`, Sharp1 Balanced `dde763c8…`, Sharp1 Performance `72246ede…`.

**Дизайн внешнего процесса (черновик):** одна вкладка «AnimeJaNai V3.1» с выбором из четырёх моделей. Backend запускает отдельный Python-скрипт: `ffmpeg` декодирует кадры, `onnxruntime-gpu` (провайдер CUDA, при наличии TensorRT) обрабатывает их в fp16, `ffmpeg` кодирует результат и возвращает исходную звуковую дорожку и FPS. Скрипт сообщает прогресс по кадрам, отмена убивает процесс. Это новый тип задачи рядом с ComfyUI, его надо вписать в `JobManager`. Скорость на Blackwell не измерена; ONNX Runtime с CUDA 13 на этой карте не проверен.
