# Локальная видеомастерская — mock-интерфейс

## Контекст

В `vast-video-pipeline` сейчас нет пользовательского веб-интерфейса. Первый этап — проверить локально полный интерфейс генерации и upscale до подключения реального ComfyUI/Vast backend.

## Цель

Добавить локальное web-приложение с первым экраном готовности Vast-машины и двумя рабочими вкладками: «Генерация» и «Upscale». Все этапы выполняются только в mock-режиме; интерфейс явно сообщает, что Vast, GPU и реальные модели не запускаются.

## Что изменится

- `web/` — отдельное Vite + SolidJS + TypeScript + Tailwind CSS приложение, запускаемое локально.
- `web/src/App.tsx` — SolidJS рабочая поверхность с режимами, загрузками, промтом, прогрессом, предпросмотром и скачиванием.
- `web/src/mock-pipeline.ts` — локальный typed mock pipeline и последовательности этапов; сетевых вызовов нет.
- `web/src/mock-video.ts` — короткий demo WebM, создаваемый браузером через Canvas/MediaRecorder.
- `web/src/model-readiness.ts` — typed стадии подготовки, с модельным списком, импортированным из существующего `config/models.lock.json`.
- `web/src/styles.css` — Tailwind CSS, responsive UI и дизайн-токены; варианты интерактивных состояний задаются через `tailwind-variants`.
- `web/src/**/*.test.ts` — unit-тесты валидации и последовательностей состояний.
- `web/e2e/` — browser smoke сценарии mock generation и upscale.
- `.gitignore` — исключения для frontend build/test artifacts; видеорезультаты остаются только в браузере и не сохраняются в репозитории.
- `web/README.md` — инструкция запуска и проверки локального mock UI.

## Дизайн-система

- Аудитория: автор видео, который загружает материалы и проверяет их обработку.
- Задача: быстро подготовить генерацию или upscale и видеть ход задания.
- Тон: предметная видеомастерская, без маркетинговой подачи.
- Направление: atmospheric / Bloom — светлая нейтральная поверхность, графитовый текст, один красно-оранжевый акцент.
- Типографика: локально упакованные Geist и IBM Plex Mono; моноширинный шрифт только для метаданных и стадий.
- Макет: верхняя панель и две вкладки; на desktop — асимметричная рабочая область ввода и preview/progress, на узком экране — один столбец. До 9 изображений показываются контактным листом.
- Декор не имитирует browser chrome; визуальный акцент — контактный лист и читаемая лента этапов.

## Детали реализации

1. При каждом открытии локального UI первым показывается экран готовности машины. Он автоматически симулирует последовательную загрузку и SHA-256-проверку 7 обязательных моделей из `config/models.lock.json`, затем — готовность ComfyUI. Список, размеры и общий объём не дублируются вручную.
2. Экран готовности показывает общий процент и отдельный прогресс каждой модели: ожидание → загрузка → проверка → готово. После завершения пользователь может открыть студию; из студии можно вернуться к статусу и повторить mock-подготовку.
3. Все файлы обрабатываются локально в браузере; допустимы одно референс-видео и до 9 референсных изображений. Изображение сверх лимита отклоняется с понятной ошибкой.
4. «Генерация» принимает промт и необязательные референсы, показывает длительность 5–15 секунд и checkbox Turbo LoRA, запускает детерминированные mock-этапы и показывает результат в `<video>`. UI явно помечает ожидаемую длительность как mock; реальная длительность H3 вычисляется по `specs/h3-generation-controls.md`.
5. «Upscale» принимает одно видео и переключатель x2/x4; прогресс явно помечен как demo.
6. Demo WebM создаётся браузером из загруженного video/image либо нейтральной canvas-сцены, чтобы preview и скачивание работали без файла-ассета в репозитории. Для generation его длительность имитирует рассчитанную native длительность H3; это не доказывает работу H3, GPU или разрешение 1344×768. Результат содержит видимую маркировку demo/mock.
7. После завершения пользователь может проиграть и скачать WebM. Ошибки формата/лимита отображаются рядом с соответствующей загрузкой.
8. Mock-stage progress, загрузки, tabs и скачивание доступны с клавиатуры и имеют видимый focus state. На ширинах 320, 375, 414, 768 и 1280 px горизонтальной прокрутки нет.
9. Для локального запуска привязать dev server к `127.0.0.1`; не обращаться к внешним API.

## Критерии приёмки

- [x] При открытии первой появляется страница готовности с 7 моделями из `config/models.lock.json`, их индивидуальным и общим mock-прогрессом, проверкой файлов и готовностью ComfyUI.
- [x] После завершения подготовки открывается веб-интерфейс с вкладками «Генерация» и «Upscale»; статус моделей доступен и из студии.
- [x] Можно добавить референс-видео и 1–9 изображений, видеть превью, удалить выбранный файл; 10-е изображение отклоняется.
- [x] Кнопка генерации требует непустой промт, дробная длительность принимается в диапазоне 5–15 секунд и отражается в demo; Turbo LoRA checkbox переключает описание режима, не запуская модель.
- [x] Upscale принимает видео и режимы x2/x4, показывает mock-этапы.
- [x] После завершения доступен проигрываемый demo WebM и работает скачивание.
- [x] Все mock-результаты, model readiness и прогресс явно маркированы; реальные модели/Vast/API не вызываются.
- [x] Unit-тесты проходят для валидации файлов и mock pipeline.
- [x] Playwright smoke проходит для обеих вкладок, результатов и скачивания.
- [x] Typecheck, lint и production build проходят.
- [x] Browser smoke не показывает console/page errors, горизонтальный overflow отсутствует на заявленных viewport ширинах.
