# Негативный промт (NegPiP) для H3, H3 Turbo и Pika

Статус: **отменено по решению Ани (2026-11-13)**: негативная нода (NegPiP) убрана из проекта, код удалён. Документ оставлен как справка.

## Почему так

В графе H3 один промт (`MiniMaxH3ReferenceToVideo.prompt`), отдельного негативного входа нет. NegPiP читает отрицательные веса из самого промта. Первая версия имела поля «Негативный промт» и «Сила», но у Ани промты уже содержат `(lit candle, candle flame, burning wick:-3)`, поэтому поля убраны.

## Внешняя нода

- `hako-mikan/comfyui-minimax-h3-negpip`, commit `f725718b4c597fab92cdb1fe981dfe3544a75665`, лицензия **AGPL-3.0** (принята Аней), запись в `config/custom-nodes.lock.json`, ставит оператор.
- Узел `ApplyMiniMaxH3NegPiP`: входы `model`, `clip`, `value_strength`, `apply_positive_weights`; выходы `model`, `clip`. Без него ComfyUI читает `(слово:-1)` как буквальный текст.

## Поведение

1. `has_negative_weights(prompt)` ищет неэкранированную группу `(текст:-число)` с необязательным `@время`. Не считаются негативом: экранированные `\(S1\)`, положительные веса `(текст:3)`, обычный текст.
2. Если группа есть, `apply_negpip(graph)` вставляет узел 60: `model` берётся после LoRA, `clip` из загрузчика; его выходы идут в `BasicGuider`, `BasicScheduler` (если у него есть `model`) и `MiniMaxH3ReferenceToVideo.clip`. `apply_positive_weights=False`, `value_strength=1.0`.
3. Если группы нет, граф идентичен прежнему.
4. Pika: общий сборщик вызывается с `wire_negpip=False`, узел подключается после LoRA Pika.

## Не подтверждено (проверяется на GPU)

- Работа узла с INT8-моделью, Turbo/Pika LoRA и референсами.
- Поведение тегов `<d>…</d>` и экранированных скобок при включённом узле; достаточность веса -3.
- `@время` автор называет нестрогим.

## Проверки

Юнит-тесты: распознавание групп, графы Base, Turbo, Pika с негативом и без; E2E и сборка без изменений интерфейса.
