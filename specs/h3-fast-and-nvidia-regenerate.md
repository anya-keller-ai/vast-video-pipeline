# MiniMax H3 Fast и NVIDIA Open-H3-Regenerate-2K в мастерской

> **Обновление 2026-11-09:** H3 Fast и NVIDIA Regenerate-2K убраны из кода по решению Ани (Fast не подошёл, Regenerate не нужен). Документ сохранён только как история решений и ничего не описывает в текущей реализации.

## Контекст

Решение Ани: в мастерской добавить (1) таб **MiniMax H3 Fast** — двухпроходная генерация на уже установленной **H3 ConvRot INT8 Unpruned** (15 шагов в низком разрешении, 3D-апскейл латента ×2, 5 шагов в финальном); (2) **NVIDIA Open-H3-Regenerate-2K** как второй вариант апскейла рядом с SeedVR2 (вход — готовое видео, выход — 2K). Основная модель H3 не заменяется (ни Pruned, ни GGUF, ни Turbo/Pika для Fast). Существующие модели и workflow не удаляются.

## Найденные факты (проверено по первоисточникам)

- Regenerate-2K работает как **refiner-LoRA поверх H3 в ComfyUI**: видео → VAE encode → 3D latent upscale на целевую сетку → re-noise σ 0.8 → **3 шага Euler** (0.8 → 0.686 → 0.48 → 0, CFG 1) → быстрый VAE decode. Звук по умолчанию — закодированная тишина; можно взять саундтрек черновика (опция узла). Это **не** «видео на вход и на выход без перекодирования»: нужна проверка сохранения оригинального звука.
- Два набора узлов: `rdh9616/ComfyUI-Open-H3-Regenerate` (с Video-to-H3-Prompt, Fast VAE, сохранением латента) и `1038lab/ComfyUI-Open-H3-Regenerate-2K` (один узел `AILab_OpenH3_Regenerate_2K`, автозагрузка весов, **лицензия GPL-3.0**). Оба требуют узел `LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler`; rdh тестировался на **ComfyUI 0.42.0**, на сервере была **0.36.0** (совместимость не проверена).
- Веса (HF): LoRA 8,8 ГБ (1038lab BF16) / 1,96 ГБ (r128) / 12,45 ГБ (оригинал NVIDIA, `license:other`); `sharp_curve_branches` 1,24 ГБ; Fast VAE 6,47 ГБ; 3D latent upscaler 0,69 ГБ. Базовая модель для Regenerate в README 1038lab — **`minimax_h3_ref2va_pruned_int8_convrot` (20,97 ГБ)**; у rdh — FL2VA любой вариант (INT8 34,04 / pruned INT8 20,97 ГБ) **плюс** pruned ref2va для таблицы `adaln_t_table` (читаются 32 КБ).
- **Sol-Attn, Fused Modulation, «Speed x6 workflow»**: источников и узлов не нашла (поиск по GitHub пуст). Реализовывать их нельзя до подтверждения реального узла; их нельзя подменять молча.
- На Vast-инстансах карта RTX 4090 с **48 ГБ** (в handoff указано 24 ГБ), диск 150 ГБ. Уже используется около 67 ГБ (H3) + 21 ГБ (SeedVR2) + 2 ГБ (Pika).

## Ограничения и конфликты

1. Regenerate по README требует **pruned**-checkpoint, а правило handoff запрещает Pruned для основной модели. Для этапа Regenerate нужно явное разрешение.
2. Диск: основной вариант Regenerate (ref2va pruned 21 + LoRA 8,8 + sharp 1,2 + upscaler 0,7 ≈ **32 ГБ**) помещается вместе с остальным (≈ 122 ГБ из 150 при запасе 20 ГБ). Вариант с FL2VA INT8 (+34 ГБ) **не помещается**.
3. Лицензии: MiniMax H3 Community License, NVIDIA `license:other`, узлы 1038lab GPL-3.0 — использование уточнить перед production.
4. Цель «15-секундное видео за 4–5 минут» — экспериментальная; результат зависит от железа.

## Что изменится (после утверждения и появления GPU-сервера)

1. **Этап 0 (аудит сервера, только чтение):** версия ComfyUI, CUDA/PyTorch, VRAM/RAM, наличие `LatentUpscaleModelLoader`/узла LBH, Sage-attention узлов, Open-H3 узлов; без установки и без перезапуска ComfyUI.
2. `config/models.lock.json`: ассеты Regenerate (LoRA, sharp curve, Fast VAE, latent upscaler, pruned ref2va) с закреплёнными revision/размером/SHA-256; bundle `h3_fast` (общие файлы H3) и bundle `regenerate_2k`; custom nodes закрепляются commit-хэшем, без выполнения неаудированных setup-скриптов.
3. `workflows/h3-fast-api.json`, `workflows/nvidia-regenerate-2k-api.json` и builders в `web/backend/`: Fast с переключателями оптимизаций (SageAttention и подтверждённые) для A/B; Regenerate принимает видео и выдаёт 2K; «Full Pipeline» (Fast → Regenerate) собирается из двух шагов.
4. `web/src/App.tsx`: таб «MiniMax H3 Fast» (форма как у H3, при необходимости с аудио-референсом, переключатели оптимизаций); в табе апскейла выбор «SeedVR2 / NVIDIA Regenerate 2K». Отмена и таймер уже работают для новых режимов.
5. Бенчмарки: замеры времени уже даёт таймер; VRAM/RAM фиксируются отдельным скриптом `scripts/benchmark-h3.sh` по таблице из handoff (5 с, затем 15 с).
6. Тесты, README, CONTEXT.md.

## Критерии приёмки

- [ ] Основная модель — только установленная H3 INT8 Unpruned; поддержка Ref2VA (референсы и черновое видео) сохранена.
- [ ] 15+5 шагов с 3D latent upscale ×2 выполняются на реальном GPU; каждая оптимизация включается/выключается отдельно; нет скрытого fallback (если узел недоступен, запуск блокируется с причиной).
- [ ] Regenerate-2K запускается отдельным этапом на готовом видео и даёт 2560×1440, 24 fps, оригинальный звук подтверждён измерением (сравнение аудиодорожек).
- [ ] Три запускаемых JSON-workflow (Fast, Regenerate, Full); реальные замеры по таблице handoff на доступной карте.
- [ ] Тесты, lint, типизация, сборка, E2E, `git diff --check`; реальный GPU-смоук подтверждён.

## Решения Ани (получены) и результаты поиска

1. **Pruned:** запрещён для основной генерации H3 Fast; разрешён только для этапа Regenerate (как интерпретировала ответ «нет, да»).
2. **Узлы Regenerate:** выбрано мной, «тот что лучше» — **`rdh9616/ComfyUI-Open-H3-Regenerate`**: он повторяет референс NVIDIA (сетка шагов 0.8 → 0.686 → 0.48 → 0, FL2VA + merged LoRA, звук можно взять из черновика, Fast VAE, сохранение латента до декода). У `1038lab` другая сетка сигм (0.909 → 0.857 → 0.667 → 0), нет соответствия референсу, и узел сам скачивает веса (это нарушает правило «только по кнопке и с закреплёнными SHA»). Минус rdh: заявлен тест на ComfyUI 0.42.0, а на сервере 0.36.0; это проверяется на этапе 0, обновление ComfyUI только по отдельному согласованию.
3. **Карта:** RTX 4090 48 ГБ.
4. **Аудио-референс:** нужен в форме Fast.
5. **Sol-Attn найден.** Sol-Attn это ядро NVIDIA (nvlabs.github.io/Sana/Sol-Attn/). Готовые узлы для ComfyUI: **`r-vage/ComfyUI-sol-attn`** (Apache-2.0, продолжение удалённого `Saganaki22/ComfyUI-sol-attn`), узлы `MiniMax H3 Memory Efficient Sol Attention`, `Scheduled Sol Attention`, **`MiniMax H3 Fused Modulation`** (точная fusion модуляции), `Chunk FeedForward`; заявленная поддержка ComfyUI **0.30.1–0.38.0** (на сервере 0.36.0 входит), проверялось на SM89 (RTX 4070 Ti SUPER; 4090 тоже SM89), Triton 3.6.0. Ограничение из README: `Fused Modulation` нельзя сочетать с KJNodes `MiniMax H3 Low VRAM Attention` (оба патчат весь блок). «Speed x6 Workflow (Sage+Sol+Latent upscale)» опубликован на Civitai (модель 2890123), там же источник схемы 15+5. Реализации из этих репозиториев подключаются как pinned custom nodes (commit-хэш), по согласованному списку, без запуска неаудированных setup-скриптов.
5a. **Выбор Ани:** Sol-Attn берём из **`r-vage/ComfyUI-sol-attn` v0.6.7** (commit `69d2e40093`, проверен на Linux/SM89). Оригинал `Saganaki22` v0.6.2 (commit `930a4d6e43`) — запасной вариант, если r-vage несовместим с ComfyUI на сервере.
6. **Конфликт версий:** Sol-Attn (≤0.38.0) и rdh Regenerate (тест 0.42.0) могут требовать разные версии ComfyUI. Решение: на этапе 0 проверить оба на 0.36.0; если несовместимы, остановиться и согласовать план (например, раздельные запуски или обновление ComfyUI).
