# Мастерская с четырьмя модельными вкладками

## Контекст

Веб-мастерская (`web/src/App.tsx`, `web/backend/`) предоставляет независимые модельные сценарии для H3, LTX-2.5, Wan 2.1 VACE и SeedVR2 без автоматического скачивания и без смешения форматов моделей/загрузчиков. HY-OmniWeaving удалён из активного состава по решению пользователя; его файлы моделей и пользовательские данные не удаляются.

Аня подтвердила: файлы моделей можно удалять вручную, чтобы освобождать диск; автоматическое удаление моделей не разрешено.

## Цель

Сделать четыре вкладки, каждая из которых показывает только зависимости выбранного workflow. При неполной готовности вкладка показывает состав, объём и прогресс загрузки и явную кнопку «Загрузить»; после проверки всех требуемых файлов показывает интерфейс соответствующего workflow. При открытии страницы и переключении вкладок загрузка не начинается.

## Что изменится

1. `config/models.lock.json` — перейти от одного глобального списка к типизированному реестру файлов и workflow bundles с источником, точным путём, размером, SHA-256, целевым путём, форматом и loader/runtime contract.
2. `config/presets.json` и `workflows/` — зафиксировать параметры конкретных ComfyUI workflows и допустимые значения UI; необязательные компоненты перечислять зависимостью только у использующего их сценария.
3. `web/backend/models.py`, `readiness.py`, `jobs.py`, `workflows.py`, `server.py` — per-bundle validation/download/status/delete, модельно-специфичные API/jobs, общий GPU job lock и предзапусковые проверки.
4. `web/src/App.tsx`, `model-readiness.ts`, `real-connection.ts`, `styles.css` — четыре вкладки, scoped readiness/download controls и формы соответствующих workflow.
5. Unit/API/E2E tests и `web/README.md` — новые состояния, файлы, workflow поля, ограничения памяти/диска и запуск.

## Детали реализации

### Общая модель данных и безопасность

1. Вкладки: `Minimax H3`, `LTX 2.5`, `Wan 2.1 VACE`, `SeedVR2`.
2. На каждый конкретный режим определяется минимальный manifest bundle. Сначала выбирается режим/вариант, затем UI показывает и загружает только файлы, нужные именно ему. Общие файлы повторно не скачиваются.
3. Переход в incomplete-состояние не запускает сеть. Только явное нажатие «Загрузить модели» создаёт одну проверяемую загрузочную задачу. Повторный клик не создаёт параллельный downloader; доступны статус, отмена и безопасный повтор.
4. `ready` означает совпадение размера и SHA-256 с lock manifest, а не наличие файла, успешный HTTP download или распаковку. Неизвестный размер/hash блокирует загрузку до фиксации проверенных метаданных.
5. Для каждого asset закрепить `format` и конкретную пару loader/workflow. Нельзя переименовывать или подавать Q5/PQ5, GGUF, FP8, INT8, BF16, `.bin`, `.pt` и обычный safetensors в неподходящий loader; нельзя автоматически преобразовывать один формат в другой.
6. Не скачивать Git-репозитории целиком и не загружать все файлы Hugging Face repo. Скачать только lock-listed файлы и минимальные необходимые исходники интеграции с закреплённым commit/hash и allowlist файлов. Не выполнять upstream `setup.py`, clone/install hooks или произвольные install scripts на сервере без аудита.
7. Общая реальная GPU очередь эксклюзивна между четырьмя вкладками: одновременно исполняется не больше одного GPU workflow. При занятом GPU другая вкладка сообщает причину и не отправляет workflow. Перед запуском сверять ComfyUI/runner availability и доступную VRAM; не убивать чужие процессы и не обещать устранение OOM, если память занята внешней моделью.
8. Диск проверять до старта transfer: показать требуемый объём выбранного workflow и свободное место; блокировать загрузку при недостатке места. Ни одна модель, partial активной загрузки, пользовательский input/output или общий файл не удаляется автоматически.
9. Ручное удаление доступно из управления моделями внутри вкладки. Показать конкретные файлы и освобождаемый размер, запросить подтверждение, блокировать удаление активной загрузки/используемой моделью job. Общие assets удалять только если они больше не нужны ни одному установленному bundle; пользовательские результаты/inputs не удалять.
10. ComfyUI и остальные runtime обслуживаются отдельно от UI. Runtime изолировать и использовать только явно перечисленные зависимости; никогда не передавать модельные форматы в несовместимый loader.

### Состав вкладок и формы

1. **Minimax H3** — сохранить текущую рабочую форму и API: prompt; до 9 reference images; optional reference video; duration 5–15 s с существующей H3 frame-grid; Turbo LoRA toggle. Bundle включает текущие unpruned diffusion, text encoder, video/audio VAE; Turbo LoRA требуется только при включённом Turbo workflow.
2. **LTX 2.5** — селектор `Dev` / `Distilled`; режимы `Text → Video` / `Image → Video`; prompt; image только для I2V; duration; output aspect/resolution и FPS из поддерживаемых значений workflow; seed; advanced steps/CFG только если соответствующий workflow принимает их. Выбранный transformer загружать отдельно, не скачивать второй вариант. Text encoder, projector, video/audio VAE и другие файлы — только точные checkpoint-файлы, которые требует закреплённый workflow; не выводить тип/формат по имени модели. Distilled LoRA для Dev, Union/Layout/Pixel LoRA и spatial/temporal upscalers — opt-in зависимости отдельных режимов, не базовые обязательные файлы. Если workflow использует альтернативные Video VAE (`Conv` или DiffVAE), закрепить и скачивать только выбранный им вариант.
3. **Wan 2.1 VACE** — режимы, подтверждённые закреплёнными workflow (первоначально `Control Video`; `Reference → Video` включать только если отдельный проверенный graph поддерживает его); prompt; control-video вход; optional mask только для graph редактирования с маской; выходная длина/FPS и разрешение ограничиваются текущим source/graph; seed и advanced sampling settings — только поддерживаемые workflow. Базовый bundle включает один VACE transformer, один text encoder и VAE с точно зафиксированными format-loader контрактами. Не скачивать альтернативную квантизацию параллельно.
4. **SeedVR2** — input video; upscale ×2/×4; preserve-aspect; FPS/audio наследуются от источника; безопасный `batch_size=1` по умолчанию; advanced параметры только из проверенного графа. Базовый bundle — Sharp 7B + VAE; не загружать H3/LTX/VACE зависимости в этой вкладке.

### Экраны и статусы

- Активная вкладка содержит свои статусы assets: `Не загружена`, `Загрузка`, `Проверка SHA-256`, `Готово`, `Ошибка`.
- Если workflow bundle не готов, вместо формы исполнения показываются нужные файлы, общий/по-файловый размер, свободное место, прогресс и явная кнопка загрузки.
- Если workflow bundle готов, показывается его работающая форма; необязательные функции, чьи веса отсутствуют, отключены с отдельным действием загрузить именно эти зависимости.
- Никакая вкладка не блокирует остальные по readiness. Общие summary-показатели могут показывать `готово X/4 сценариев`, но не запускают загрузку.
- Ошибки отсутствующего custom node, отсутствующего модели, неизвестного формата, недостающего диска/VRAM и недоступного backend показываются раздельно.
- Во время активной загрузки интерфейс последовательно опрашивает backend не реже чем раз в 500 мс и показывает скорость по недавнему окну передачи и примерный ETA; при остановке прогресса не сохраняет устаревшую оценку.

## Критерии приёмки

- [x] Рендерятся четыре вкладки; E2E подтверждает, что переключение не запускает повторный API bundle request, transfer или workflow, а HY вкладка отсутствует.
- [x] Неполная выбранная конфигурация показывает свой bundle; transfer начинается только после явного действия пользователя.
- [x] Readiness сверяет размер и SHA-256; per-bundle download/cancel/retry защищён от дубликатов и проверяется mocked tests.
- [x] LTX Dev/Distilled разделены на отдельные bundles; для выбора загружается только выбранный bundle.
- [x] Существующие H3 controls/regressions сохранены; SeedVR2 имеет отдельную upscale-форму. LTX остаётся заблокирован до проверки graph. Wan VACE Control graph реализуется отдельно; execution остаётся заблокирован до реального GPU smoke.
- [x] Для каждого asset lock фиксирует format/loader/runtime; unknown formats и отсутствующие runtime не передаются в неподходящие loaders.
- [ ] GPU queue сериализуется и unknown/zero VRAM блокирует workflow, но per-workflow minimum free VRAM thresholds ещё не проверены и не закреплены. Positive free VRAM сам по себе не гарантирует отсутствие OOM.
- [x] Недостаток свободного диска блокирует загрузку; manual delete требует подтверждения, shared assets и active jobs/downloads защищены.
- [x] Backend: 65 tests, Ruff check/format, basedpyright clean; frontend: 21 unit tests, 5 Playwright E2E, typecheck, ESLint, production build и `git diff --check` прошли.
- [x] Верификация использовала mocks/local browser; model weights не скачивались, GPU workflows не запускались, коммитов нет.
- [x] Активная загрузка опрашивается с интервалом 500 мс без наложения запросов и показывает скорость/примерное время по последним 5 секундам прогресса.
