# Частота обновления загрузки и оценка скорости

## Контекст

Статус загрузки model bundle сейчас опрашивается раз в секунду, поэтому прогресс выглядит редким. В UI также не показываются текущая скорость и примерное оставшееся время.

## Цель

Во время активной загрузки обновлять интерфейс два раза в секунду и показывать сглаженную скорость передачи и оценку времени до завершения.

## Что изменится

1. `web/src/App.tsx` — интервал опроса состояния активной загрузки 500 мс и отображение скорости/ETA.
2. `web/src/model-bundles.ts` — типизированный расчёт телеметрии по недавним снимкам прогресса.
3. `web/src/model-bundles.test.ts` — unit-тесты скорости, ETA, недостатка данных и сброса при немонотонном прогрессе.
4. `specs/multi-model-workbench.md` — документирование поведения.

## Детали реализации

1. Пока активна загрузка или проверка моделей, последовательно опрашивать backend каждые 500 мс; не допускать параллельных запросов.
2. Оценивать скорость по изменению суммарных загруженных байтов за последние 5 секунд; выводить МиБ/с.
3. Рассчитывать ETA как оставшиеся байты, делённые на положительную оценку скорости.
4. До накопления достаточных данных, при нулевой скорости или сбросе прогресса показывать нейтральное «Рассчитываю…», а не устаревшую или отрицательную оценку.
5. Не менять логику старта/отмены загрузок и не запускать загрузку автоматически.

## Критерии приёмки

- [x] Активная загрузка опрашивается с интервалом 500 мс без наложения запросов.
- [x] UI показывает скорость в МиБ/с и примерное оставшееся время, когда оценка доступна.
- [x] При недостатке данных, нулевой скорости и сбросе прогресса ETA не показывается как достоверная.
- [x] Unit- и Playwright-тесты проверяют расчёт скорости/ETA и крайние случаи без сетевых запросов и скачивания моделей.
- [x] Frontend unit-тесты, typecheck, lint и production build проходят.
