# Опорные кадры «Add Guide for MiniMax H3»

Статус: **реализовано** (решения Ани 2026-11-13: все три вкладки, позиция в кадрах, максимум 4, без аудио-якорей). Не проверено на живом ComfyUI и GPU: сервера нет.

## Цель

В формах H3, H3 Turbo и Pika H3 Flex добавить блок «Опорные кадры»: пользователь прикрепляет картинки и указывает, на каком кадре (секунде) ролика каждая должна стоять. Видео обязано пройти через эти кадры.

## Проверенные факты (исходник ComfyUI `comfy_extras/nodes_minimax_h3.py`)

- Узел **встроенный**, `MiniMaxH3AddGuide` («Add Guide for MiniMax H3», категория `model/conditioning/minimax`), добавлен в ComfyUI 2026-08-13 (PR #15439). Он есть в версии, закреплённой в нашем образе (`5ba116a`), ставить ничего не нужно.
- Входы: `positive` (CONDITIONING), `latent` (AV-латент H3), `vae` (нужен при картинке), `audio_vae` (нужен при аудио), необязательные `image`, `audio`, `frame_idx` (-9999…9999; отрицательные считаются с конца). Выход: `positive`.
- Картинка: берётся первая; пачка из ≥5 кадров якорится как клип длиной 17k+5 кадров (5, 22, 39…). Размер приводится к кадру: обрезка по центру (`center`).
- Ошибка, если `frame_idx` выходит за длину видео, или если нет ни картинки, ни аудио.
- Узлы **цепочкой**: `positive` одного идёт в следующий. Список якорей накапливается в `minimax_keyframes` кондиционирования.
- Узел работает с выходами `MiniMaxH3ReferenceToVideo` (кондиционирование и AV-латент), то есть подходит к нашему графу.
- В репозитории шаблонов есть картинки `h3_frame_ref_1…4.png` (шаблон «Multiframe Reference», по словам Ани). Сам JSON шаблона не читала: его точные параметры не подтверждены.

## Предлагаемый дизайн

1. **Граф.** Для каждого якоря узел `MiniMaxH3AddGuide` (id 70+i): `positive` = выход предыдущего (первый берёт `["7", 0]`), `latent` = `["7", 1]`, `vae` = `["3", 0]`, `image` = `LoadImage` (id 80+i), `frame_idx` = номер кадра. `BasicGuider.conditioning` переключается на выход последнего якоря. Без якорей граф не меняется. NegPiP не конфликтует (он правит `model` и `clip`, якоря кондиционирование).
2. **API.** В `POST /api/jobs` (режимы `generation`, `pika`) поле `guides`: массив `{imageId, second}`. Backend переводит секунду в кадр (24 fps) и проверяет, что кадр внутри клипа (0…frames-1).
3. **Интерфейс.** Блок «Опорные кадры»: добавить картинку, поле «Секунда» (с шагом в один кадр), удалить. Подсказка про расчёт кадра.
4. **Проверки.** Юнит-тесты цепочки (1, 3 якоря; без якорей граф прежний; Turbo и Pika), валидация, E2E формы. После этого один пробный запуск на GPU (только по просьбе Ани).

## Риски (не подтверждено)

- Совместимость с INT8-моделью, Turbo LoRA и LoRA Pika, взаимодействие с референсами `<Picture N>` (картинка-якорь и картинка-референс могут быть одним файлом).
- Сколько якорей и на каких кадрах модель держит без артефактов: проверяется только на GPU.
